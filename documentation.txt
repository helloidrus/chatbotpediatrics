3. Alur Pipeline (Runtime)
1. Query masuk melalui src/run_chat.py.
2. src/pipeline.py melakukan retrieval context dengan Retriever.
3. LLM menghasilkan draft_response melalui Generator.
4. RuleEngine melakukan verifikasi:
- ekstraksi fakta dari draft_response menggunakan src/verification/fact_extractor.py
- pencocokan fakta/jawaban terhadap aturan di src/verification/rule_pediatri.json
- menghasilkan verified_response (boleh sama dengan draft_response atau hasil modifikasi/blocking rule).

4. Catatan Implementasi Verification
- RuleEngine saat ini self-contained (load rule + evaluasi kondisi di satu file).
- Rule default path:
  - src/verification/rule_pediatri.json
- Fact extractor verifikasi menggunakan spaCy rule-based matcher.

5. Perintah Operasional yang Dipakai
- Ekstraksi PDF:
  - python src/ingestion/extract_ppm.py
- Cleaning teks:
  - python src/ingestion/clean_ppm.py
- Chunking:
  - python src/ingestion/chunk_ppm.py
- Build index:
  - python src/ingestion/build_index.py
- Jalankan chat:
  - python -m src.run_chat

6. Catatan Penting
- Pada src/pipeline.py, pemanggilan LLM saat ini masih dalam mode testing:
  - draft_response hardcoded.
  - baris generate dari LLM masih dikomentari.
- Jika ingin kembali ke mode produksi, aktifkan kembali:
  - draft_response = self.generator.generate(query, context)
  - lalu nonaktifkan hardcoded draft_response testing.

  - `draft_response` masih hardcoded.

9. Update Hari Ini (2026-03-05)
- Fokus perubahan: sinkronisasi penuh sistem verifikasi agar mengikuti skema rule aktif di `src/verification/rule_pediatrics.json`.
- Pemeriksaan menyeluruh ulang dilakukan pada jalur runtime:

- Perubahan di `src/verification/rule_engine.py`:
  - Menambahkan dukungan evaluasi rule diagnosis untuk field:
    - `required_parameters`
    - `expected_symptoms`
    - `required_tests`
  - Menambahkan evaluator kategori rule:
    - `symptom_management`
    - `emergency`
  - Memperbaiki evaluator `treatment` agar mendukung kondisi rule berbasis:
    - `if.diagnosis`
    - `if.symptom`
  - Menambahkan metadata rule ke setiap violation agar keputusan bisa mengikuti JSON:
    - `category`
    - `severity`
    - `action_if_violation`

- Perubahan di `src/verification/claim_extractor.py`:
  - Menambahkan ekstraksi `treatments` agar rule kategori treatment/symptom management dapat match.
  - Menambahkan ekstraksi `actions` (contoh: `rujukan_segera`) agar rule kategori emergency dapat diverifikasi.
  - Struktur output claims kini mencakup:
    - `symptoms`, `diagnosis`, `clinical_parameters`, `tests`, `treatments`, `medications`, `actions`.

- Perubahan di `src/verification/decision_layer.py`:
  - Keputusan tidak lagi hanya berdasarkan jenis pelanggaran dosis.
  - Logika keputusan sekarang mengikuti metadata rule dari JSON:
    - Jika ada `action_if_violation = override` -> `OVERRIDE`.
    - Jika ada `action_if_violation = regenerate` atau `severity = critical` -> `REGENERATE`.
    - Selain itu -> `WARNING`.

- Perubahan di `src/pipeline.py`:
  - Menghapus import yang tidak dipakai: `from src.llm import generator`.
  - Menambahkan handling untuk aksi `OVERRIDE` pada hasil decision layer.
  - Memperbaiki pemanggilan regenerate agar kompatibel dengan signature generator:
    - dari `self.generator.generate(prompt)`
    - menjadi `self.generator.generate(prompt, "")`.
  - Rule path aktif tetap:
    - `src/verification/rule_pediatrics.json`.

- Perubahan di `src/llm/generator.py`:
  - API key tidak lagi hardcoded; sekarang membaca environment variable:
    - `GROQ_API_KEY` atau `OPENAI_API_KEY`.
  - Signature method diubah agar kompatibel dengan mode regenerate:
    - `generate(self, query, context="")`.

- Kondisi file `src/run_chat.py`:
  - Sudah konsisten menerima 5 nilai return dari pipeline:
    - `answer, retrieved, scores, violations, decision = pipeline.run(query)`.

- Validasi teknis yang dijalankan hari ini:
  - Syntax validation:
    - `python -m py_compile src/verification/rule_engine.py src/verification/claim_extractor.py src/verification/decision_layer.py src/pipeline.py src/run_chat.py` -> sukses.
  - Uji skenario rule cepat:

10. Update Hari Ini (2026-03-07)
- Fokus perubahan: menutup gap verifikasi dosis obat untuk format rentang serta merapikan konsistensi normalisasi teks di claim extractor.
- Pemeriksaan error runtime dilakukan pada alur:
  - `src/run_chat.py` -> `src/pipeline.py` -> `src/verification/claim_extractor.py`.
  - Error yang dianalisis: `ValueError: invalid literal for int() with base 10: '10-15'`.

- Perubahan di `src/verification/claim_extractor.py`:
  - Parsing dosis obat diperbarui agar mendukung:
    - angka tunggal, contoh: `10 mg/kg` -> field `dose`
    - rentang angka, contoh: `10-15 mg/kg` -> field `dose_min` dan `dose_max`
  - Konversi dosis tidak lagi langsung `int(match.group(2))`; sekarang mengekstrak angka dengan regex agar aman untuk format rentang.
  - Konsistensi normalisasi teks diperbaiki:
    - pemeriksaan `clinical_parameters`, `tests`, `treatments`, dan `actions` kini konsisten memakai `text_lower`.

- Perubahan di `src/verification/rule_engine.py`:
  - Fungsi `check_medication_rules` diperbarui agar memvalidasi dua skema data dosis:
    - `dose` (single value)
    - `dose_min/dose_max` (range value)
  - Rule violation sekarang tetap terdeteksi untuk kasus seperti `parasetamol 10-16 mg/kg` terhadap batas guideline `[10, 15]`.

- Dampak perubahan:
  - Kasus dosis rentang yang sebelumnya bisa lolos verifikasi karena `dose` bernilai `None` sekarang sudah tertangkap sebagai `dose_violation`.
  - Alur `decision_layer` akan menerima violation yang benar sehingga keputusan tidak salah `PASS` untuk dosis rentang di luar batas rule.

- Validasi teknis yang dijalankan hari ini:
  - `python -m py_compile src/verification/claim_extractor.py` -> sukses.
  - `python -m py_compile src/verification/rule_engine.py src/verification/claim_extractor.py src/pipeline.py` -> sukses.
